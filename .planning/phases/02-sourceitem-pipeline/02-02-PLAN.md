## Planner decisions recorded for this plan

- **Claude's discretion, chosen here:**
  - Social NER input is the title, a newline, then the text, cut to the first 500 `char`s. That is the same cap map-extract uses for `body_preview` (smartmodules/map-extract/src/lib.rs:393) and stays inside GLiNER-small's context (A6). News NER input stays `text` (= body_preview), exactly as before, so news enrichment does not regress.
  - The streams are merged with `futures_util::stream::select`.
  - The narrowing flag is `--source <both|news|social>`, a clap `ValueEnum` defaulting to `both` (RESEARCH Open Question 2).
  - Phase 2 tests produce social items with the existing `TypedProducer` against scratch topics in `#[ignore]` tests. No new user-facing produce command is added, because that belongs to Phase 3 and 4.
- **Topic of origin wins.** `decode_social` labels every record read from the social topic as social, whatever it claims (RESEARCH Security Domain: record spoofing).
- **Unchanged on purpose:**
  - `load_ner_engine` keeps its silent fallback when the model is missing (existing behaviour, RESEARCH Open Question 1). SC4 is proven with an injected detector, and the live model run is a human-check.
  - Streaming mode (`--limit 0`) keeps no NER and no JSON file.
  - `--threshold` stays unwired.

    - ner_input_keeps_news_text: a news record's NER input equals its `text` byte for byte.
    - ner_input_truncates_by_chars: a social record with title None and text of 600 `é` gives an input of exactly 500 chars (1000 bytes). Text of 501 `🦀` gives exactly 500 `🦀`. A title of 499 chars plus a text gives 500 chars, ending inside the text.
    - empty_ner_input_skips_detector: a social record with title None and text empty, or only whitespace, means the detector is never called and `entities` stays empty.

| operator CLI flag `--output` → local filesystem | An operator-supplied path; no path is ever taken from record content. |
