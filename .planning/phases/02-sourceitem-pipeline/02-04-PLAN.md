<objective>
Close the one verification gap of Phase 2: a consume diagnostic can carry record content and raw terminal control bytes. This fails the "no diagnostic carries the record value" prohibition of 02-01 (news stream) and 02-02 (social stream). It is the same root cause as code review CR-01 and the reopened SECURITY threat T-02-02, and this plan closes both.

SmartModule hints are cut to the text the module itself wrote. Every diagnostic reaches stderr through one sanitizing choke point. The two failed prohibitions then hold in the code, proven by tests that use the verifier's own reproduction inputs and by two cluster tests on the real chain and topic.
Output: changes to `src/commands/consume.rs` only (two new helpers for content-free diagnostics, one stderr choke point, removal of the quote-toggle redactor), six new unit tests and two new `#[ignore]` cluster tests.

## Planner decisions recorded for this plan

- **Structured accessors, not a better redactor (checked at plan time).** serde's `Unexpected::Str` prints string values with Debug inside double quotes, so inner quotes arrive escaped. Variant names, unknown field names, numbers and characters print with Display inside backticks and are not escaped (serde_core 1.0.228 `de/mod.rs`: ``Str(s) => write!(formatter, "string {:?}", s)``, ``"unknown variant `{}`, expected {}"``). A value such as a, backtick, b, backtick, `PAGE-BODY` defeats any backtick toggle. So no redactor over Display text can be sound, and the decode paths stop reading that text. serde_json 1.0.150's `Category` has exactly four variants (`Io`, `Syntax`, `Data`, `Eof`), which makes the match exhaustive with no wildcard arm.
- **SmartModule hint: keep the module-authored prefix.** A hint is `format!("{error:?}")` of the module's eyre report (fluvio-protocol 0.50.1 `link/smartmodule.rs:32`). The three filimon modules write `Failed to parse RawPage: ` (map-preprocess `lib.rs:172`), `Failed to serialize bundle: ` (`lib.rs:182`), `Failed to parse PreprocessedBundle: ` / `Failed to serialize article: ` (map-extract `lib.rs:386`, `416`), or a bare serde error (filter-relevance `lib.rs:43`), each followed by serde_json text. eyre appends its location block after a newline. Every record-controlled piece of that text starts at a double quote, a backtick, or a newline, so the text before the first of those (or before any other control character) is module-authored. The SmartModules cannot change (D-01), so this cut happens in the consumer.
- **The choke point lives in consume.rs, not output.rs.** It formats consumer diagnostics only. Keeping it next to its three callers leaves `src/output.rs` untouched and gives this plan a single owned file.
- **Diagnostic wording is not a contract.** README.md and `.planning/codebase/*.md` do not quote any consume diagnostic (grep at plan time). The new text may differ from today's.
- **Test gate:** `cargo test -p filimon`, never `--workspace` (the map-preprocess `test_lemmatize` failure predates this phase). Every `cargo test` gate chains cargo's exit status with `&&` (never `;`) and also rejects any `test result: FAILED` line in its log, so one failing test binary fails the gate even when another binary prints `test result: ok`. Baseline at plan time: `cargo test -p filimon` exits 0 and runs one test binary (`unittests src/main.rs`: 102 passed, 3 ignored), so the exit-status chain does not fail for a pre-existing reason. The clippy gates keep their `Finished` check: clippy warnings do not change its exit status, and a compile error removes `Finished`. Cluster tests stay `#[ignore]` and use scratch topics through the existing `with_scratch_topics` helper. The local cluster was up at plan time (`fluvio topic list` and `fluvio sm list` showed the three filimon SmartModules).
- **Grep baselines (run against HEAD at plan time):** the gate for `eprintln!` outside `print_diagnostic` prints 3 lines (the three print sites), and `print_diagnostic` does not exist yet. `print_diagnostic(` = 0. `fn redact_quoted` = 1 line. Neither decode function calls `describe_json_error(&e)`. The decode functions contain 2 Display-formatting lines. `hint_summary(` inside `describe_stream_error` = 0. The D-01 diff gate already passes at HEAD on purpose: it is an invariant that must stay true.
- **Region-scoped macro gate:** `eprintln!` must be present inside `print_diagnostic` and absent everywhere else in the file. The gate checks both sides with an awk range, so the action has to name the macro.
