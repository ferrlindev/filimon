<objective>
Make `Host::run` stop in bounded time (carry-over WR-10) and give the run command the accessors it needs. The supervision loop becomes a generic function over `InstanceFactory` so it can be driven by the scripted fake in paused-time tests; after the shutdown token fires, tasks get a grace period (default 10 s) and are then aborted; a second stop request aborts at once.

Purpose: CLI-04 (success criterion 4: the run command runs until it is stopped, and stopping it must not take N x 60 s behind a stuck broker). Aborting mid-send is safe because the cursor is written only after the sink returned (D-07).

Output: `src/plugins/host/mod.rs` only. The README sentence that claims shutdown returns within seconds is corrected in plan 04-06 together with the other documentation.

Working decisions (no CONTEXT.md; from 04-RESEARCH.md; the user may override before execution):
- OQ-8: grace is a constant 10 s, a second stop request aborts immediately, an operator-initiated stop exits 0 even when tasks were aborted (the aborted plugins are named in a warning), and there is no `--shutdown-grace` flag.
- Chosen WR-10 fix: bounded grace plus abort (research F6). The alternative from the review (a deadline on the producer-lock wait) is not taken because it would not bound a hanging `send` itself.
- The grace is set with a builder method on `Host` (`with_shutdown_grace`) instead of a new `HostOptions` field, so the six existing `HostOptions { state_dir }` literals in tests do not change.

Flagged assumptions (edge probe, the user has not ruled): CLI-04 adjacency (same-instant polls stay independent) and ordering (per-plugin order preserved, cross-plugin order unspecified) are resolved here by the planner as truths above. The other CLI-04 adjacency half (two processes on one state directory) and the empty edge are in plan 04-06.
</objective>
