## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| status and registry files to the terminal and to scripts | File-derived strings are printed in tables and JSON |
| registry names to filesystem paths | A name from `filimon.toml` could be used to build a status path |
| stdout to a consuming script | Any extra text on stdout corrupts `--json` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-09 | Tampering | machine-readable output corrupted by the banner or by log text on stdout | medium | mitigate | The banner is skipped for `plugins` (plan 04-01); logging goes to stderr only; the binary test parses stdout as JSON and checks the first byte is `[`. |
| T-4-10 | Tampering | a registry name with path separators or `..` being joined into a status path | high | mitigate | `list_registry` excludes any name failing the `[a-z0-9_-]` rule and `collect_list` builds paths only from the remaining names; test `list_reports_skipped_invalid_names_and_never_uses_them_as_paths`. |
| T-4-11 | Tampering | terminal escape or line-forging characters in a hand-edited status file reaching a terminal or a JSON consumer | high | mitigate | Every file-derived string goes through `sanitize_for_terminal` or `clean_guest_text`; human output is clipped; test `list_sanitizes_status_text_from_files` asserts no ESC and no newline in table or JSON. |
| T-4-SC | Tampering | npm/pip/cargo installs | high | accept | No package is installed or added in this plan; `git diff --quiet -- Cargo.toml Cargo.lock` is an acceptance criterion. |
