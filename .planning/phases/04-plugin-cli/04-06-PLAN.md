<objective>
Deliver the run command, `fili run`: it polls every enabled source plugin on its interval and produces items to Fluvio until it is stopped. It wires `Host::load`/`Host::run_with_abort` (plan 04-02) to the production sink, `--registry` and `--state-dir`, prints load failures at startup, handles SIGINT and SIGTERM with a second-signal abort, and prints a per-plugin summary. It also closes the Phase 3 carry-overs that needed a caller: the unused-code allows, and the README claims about shutdown and poll status.

Purpose: CLI-04 (success criterion 4) and the last step of the phase goal: users can inspect (`list`), validate (`check`), try (`run-once`) and run (`run`) registered plugins without writing code.

Output: `src/commands/run.rs`, `Command::Run`, the dispatch and banner changes, removal of the blanket unused-code allow, updated READMEs, and a final phase gate.

Working decisions (no CONTEXT.md; from 04-RESEARCH.md; the user may override before execution):
- OQ-1: the run command is the top-level `fili run` with no flags beyond the global `--registry` and `--state-dir` (the alternative `fili plugins run` is rejected: it blurs inspecting with operating).
- OQ-8: grace 10 s, a second signal aborts, exit 0 on an operator stop even if tasks were aborted.
- OQ-9: exit 1 when every plugin ended disabled by a fault, when nothing is enabled or loadable, or on any startup error.
- OQ-10: components that fail to load are printed at startup and the rest run; zero loaded is an error. The strict registry load stays: one broken enabled plugin TOML blocks `fili run`, and `enabled = false` is the way to skip a plugin.
- OQ-11: the `resolved plugin secrets` info log is left as is.

Flagged assumptions (edge probe, the user has not ruled): CLI-04 empty (no enabled or loadable source is an error), adjacency (a second process on one state directory is refused) and ordering (summary sorted by name; per-plugin order preserved) are resolved by the planner as the truths above; override any before execution.
</objective>
