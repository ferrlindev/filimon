<objective>
Deliver `fili plugins run-once <name>`: one poll of one source, printing what it returned, with nothing produced to Fluvio and no state touched unless `--produce` is given.

Purpose: CLI-03 (success criterion 3). It is also the tool later phases use to check real plugins (`fili plugins run-once reddit`). The single-cycle path is new host-library code built on the existing seams (`InstanceFactory`, `PluginInstance`, `map_items`, `ItemSink`), not `run_plugin`, which loops forever.

Output: `src/plugins/host/once.rs`, small shared helpers extracted from the scheduler, a lock-free cursor read, the `run-once` command with human and `--json` output, and tests.

Working decisions (no CONTEXT.md; from 04-RESEARCH.md; the user may override before execution):
- OQ-2: human output clips fields to 200 characters and shows key, url, title, author, published and a text preview; `--json` prints one `SourceItem` per line.
- OQ-4: both modes start from the saved cursor (the dry run reads it without the lock and never writes it). There is no `--from-start` flag in this phase.
- OQ-5: `[settings]` problems surface here as a `config` poll error.
- OQ-3: a disabled source is refused by `run-once`.
- OQ-9: exit 1 for any failure including an interrupt; exit 0 on success.
- The option that enables producing is named `--produce`, as the roadmap wording says.

Flagged assumptions (edge probe, the user has not ruled): CLI-03 adjacency (equal keys all kept, dropped count shown), empty (zero items is a success with the cursor still saved under `--produce`), encoding (character-based clipping and sanitizing, serde-escaped JSON) and ordering (guest order) are resolved by the planner as the truths above; override any before execution.
</objective>

| Boundary | Description |
|----------|-------------|

| secrets to guest | Secret values leave the host only through `init` |
