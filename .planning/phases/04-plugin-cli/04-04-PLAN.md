<objective>
Deliver `fili plugins check <name>`: validate one registered plugin without polling it. The component must satisfy its declared WIT world through the host's own preflight (not a second checker), and its TOML and required `.env` secrets must be valid, with problems scoped to the checked plugin.

Purpose: CLI-02 (success criterion 2). The machinery exists: `load_source` and `load_fetcher` in `loader.rs` already compile a component, reject foreign imports and instantiate-pre against the world. They are private, and `load_registry` is all-or-nothing, so one broken plugin would fail the check of a healthy one. This plan exposes the first and adds a scoped variant of the second.

Output: `check_component` in `loader.rs`, `ConfigError::plugin` and a plugin-scoped loader in the config module, the `check` command, and binary tests (real-wasm ones are ignored and named `wasm_*`).

Working decisions (no CONTEXT.md; from 04-RESEARCH.md; the user may override before execution):
- OQ-3: `check` of a disabled source validates the component only and prints `config: skipped (plugin is disabled)`. Validating a disabled plugin's config would need a loader flag that forces it on and is not added.
- OQ-5: `check` does not run guest `init`; plugin-specific `[settings]` errors surface in `run-once` as a `config` error. An opt-in `--init` is not added.
- OQ-9: exit 0 only when every part passed; any failure exits 1.
- OQ-11: the `resolved plugin secrets` info log stays; it is a stderr line naming env var names, not values.
- Research recommended filtering a full load's problems; this plan instead scopes the loader itself to the checked plugin (a refinement of research F3 so another plugin's broken TOML or `.env` need is never even read). The `ConfigError::plugin()` accessor research asked for is added and used by that scoping.

Flagged assumptions (edge probe, the user has not ruled): CLI-02 empty (empty or unknown name and zero-byte component are errors that list what exists) and encoding (exact byte comparison, sanitized echo) are resolved by the planner as truths above; override either before execution.
</objective>
