<objective>
Give a fetcher's `outbound-http.send` import real network access, owned entirely by the host: one shared HTTP client with certificate validation on, a redirect loop that checks the allowlist on every hop, a response size cap, and one deadline for the whole call. A fetcher, default or custom, can reach only what the calling source (or the crawler) may reach.

Purpose: FETCH-02 (the host enforces the allowlist and the timeout regardless of which fetcher handles the request) and FETCH-03 (a real, certificate-validating HTTPS path under the default fetcher). TLS behaviour is proven in plan 05-05; request validation and log hygiene are plan 05-04.

Output: `Egress` and `EgressGrant` in `fetch.rs`, the grant wiring in `engine.rs`, `HostEngine::egress()`, `TestHttpServer` in `testing.rs`, and the route construction change in `mod.rs`.

Working decisions (no CONTEXT.md; the user may override before execution):
- WD-09 `send` follows redirects itself (at most five), checking the policy on every hop, and the HTTP client's own automatic redirect following stays off. This is the only way an open redirect on an allowed host cannot reach a host outside the allowlist, and it keeps the default fetcher a pure pass-through. It changes what "send one request" means for fetcher authors (documented in `wit/host.wit` by plan 05-08). Rated costly: a fetcher written against this behaviour would break if redirects ever moved back to the guest.
- WD-10 Response bodies are buffered whole up to 8 MiB (`MAX_RESPONSE_BYTES`). A larger body is `transport` with a text naming the cap; no WIT change is needed (the contract's `fetch-error` has no size case and adding a case would break guests built against 0.1.0).
- WD-11 The client's certificate roots are the ones bundled with the HTTP client's rustls configuration (webpki roots). The operating system's trust store is not read, so a TLS-intercepting corporate proxy CA is not trusted. Proxy environment variables keep their usual effect.
- WD-12 No host-side request rate limiter in this phase: FETCH-01..04 and the roadmap criteria ask for allowlists and timeouts only, and Reddit's rate-limit headers are the plugin's job (RDDT-03). A 429 response is an ordinary response.

Flagged assumptions (edge probe: FETCH-03 is `unclassified`, the user has not ruled): the trust-store choice in WD-11, and that proxy environment variables are honoured. FETCH-02 concurrency (a per-call deadline) is proven in plan 05-06.
</objective>
