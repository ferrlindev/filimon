<objective>
Let the news crawler fetch its pages through a fetcher component. A new `[crawler]` table in `filimon.toml` names the fetcher; `fili produce` reads it and, when it is present and valid, fetches the seed page and its ranked links through that component, under the host's policy (the seed urls' hosts plus any extra hosts, a timeout, certificate validation, redirects checked on every hop). With no `[crawler]`, `fili produce` behaves exactly as before.

Purpose: FETCH-04 (the news crawler can be configured to fetch pages through a fetcher component instead of its built-in client, the hook for a future headless-browser fetcher) and roadmap criterion 4 (with the crawler configured to use a fetcher, `fili produce <url>` fetches pages through it and articles still reach the consumer).

Output: the `[crawler]` config and its loader, `CrawlFetcher` in the host, `PageFetcher` in the crawler, the injectable crawl loop and the registry path in `produce`, and the dispatch change in `main.rs`.

Working decisions (no CONTEXT.md; the user may override before execution):
- WD-20 The crawler is configured by a `[crawler]` table in `filimon.toml`: `fetcher` (required, an enabled `[fetchers.*]` entry), `timeout_secs` (default 15, the built-in client's own timeout), `allowlist` (optional extra hosts). The registry flag (`--registry`, `FILI_REGISTRY`) already exists for every subcommand and now also applies to `produce`.
- WD-21 The crawler's allowed hosts are the hosts of the seed urls given on the command line, plus `[crawler] allowlist`. The crawler only follows same-host links, so every legitimate request is to a seed host. A redirect to a different host (a `www.` variant, say) is denied by name; the operator passes the final url as the seed or lists the host. There is no implicit allow-all.
- WD-22 No registry file means "no crawler configured": `fili produce` keeps working without any registry, as today, and prints one line saying it uses the built-in client. Any registry that exists but does not parse, or a `[crawler]` that cannot be used, is an error (no silent fallback to a client that skips certificate validation).
- WD-23 `load_crawler` reads the registry leniently: it needs only `[crawler]` and `[fetchers]`, so a broken source entry elsewhere in the file cannot stop `fili produce`. The strict loader (`fili run`) validates `[crawler]` too, because it is the same file.
- WD-24 The built-in client stays as it is: its certificate-validation bypass is a known gap of the existing crawler, outside this milestone (PROJECT.md), and the fetcher path must not inherit it. The only edit to `build_client` is replacing its User-Agent literal with a shared constant.

Flagged assumptions (edge probe, the user has not ruled): FETCH-04 concurrency is resolved as the bounded-hang truth (explicit) plus the interruption statement (a backstop marker the verifier cannot confirm without a human). Page text is decoded as UTF-8 with replacement for invalid bytes; the built-in client's charset-aware decoding is not reproduced. A page larger than 8 MiB fails as a transport error.

Assumption-delta note (decision recorded in plan 05-01): the crawler is a second consumer of the same routing, so this plan reuses `FetchPolicy` and `FetchRoute` with the consumer label `crawler`. The accepted debt is the extra pair of config-error variants below.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command-line seed urls and crawled pages to the fetcher | The crawler asks the fetcher for urls from the operator and for links found in untrusted HTML |
| registry `[crawler]` table to behaviour | The operator's config decides which client the crawl uses |
| fetched page to the pipeline | Page HTML is untrusted input to the SmartModule chain |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-21 | Elevation of Privilege | the crawler's fetcher being used to reach internal or arbitrary hosts (SSRF) through a seed, a link or a redirect | high | mitigate | The crawler path runs the same `FetchPolicy` as a source, with an allowlist limited to the seed urls' hosts plus the operator's `[crawler] allowlist`, checked at entry, at the fetcher's send and on every redirect hop; tests wasm_crawler_denies_a_redirect_to_a_host_that_is_not_a_seed_host, wasm_crawler_extra_hosts_allow_a_redirect_target and the invariant wasm_source_and_crawler_routes_enforce_the_same_policy. |
| T-5-22 | Denial of Service | a hung fetcher or server stalling the whole crawl | medium | mitigate | The route's single deadline is `[crawler] timeout_secs` (default 15); a timed-out page is skipped and the crawl continues; test wasm_a_hung_server_is_abandoned_at_the_crawler_timeout_and_the_crawl_moves_on. |
| T-5-23 | Spoofing | a silent fallback to the built-in client, which skips certificate validation, when `[crawler]` is configured but unusable | medium | mitigate | `select_page_fetcher` returns the built-in client only when no registry file or no `[crawler]` table exists and says so; every other problem is an error that stops `fili produce` before it connects; tests an_invalid_crawler_table_is_an_error_and_never_a_fallback, a_registry_that_is_not_toml_is_an_error_and_never_a_fallback and a_crawler_whose_fetcher_component_is_missing_is_an_error_naming_it. |
| T-5-24 | Tampering | over-broad `[crawler] allowlist` entries written by the operator | low | accept | The extra hosts are an explicit operator choice, normalized and exact-matched like every allowlist; an entry that is not a bare host is dropped and logged (plan 05-01). The default is the seed hosts only. |
| T-5-25 | Tampering | fetched page content being hostile input to the pipeline | low | accept | The fetcher path returns the same kind of data the built-in client returns (HTML text for a `RawPage`), downstream handling is unchanged, and the response is capped at 8 MiB by the host; no new parsing of page content is added here. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is added: `git diff --quiet -- Cargo.toml Cargo.lock` is an acceptance criterion of every task. |
</threat_model>
