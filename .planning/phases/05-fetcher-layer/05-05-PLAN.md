<objective>
Prove, rather than assume, that the host's HTTPS path validates certificates, and that the roadmap's "an invalid certificate fails" holds for the default fetcher: a local TLS server with a self-signed certificate is rejected, accepted only when its certificate is explicitly trusted, rejected again for the wrong name, and rejected through the real default fetcher component. A source guard keeps the invalid-certificate switch out of the fetch path on every normal run.

Purpose: FETCH-03 (the default HTTP fetcher validates TLS certificates and the crawler's disabled validation is not carried over). The client itself was built validating in plan 05-03; this plan is its proof.

Output: `src/plugins/host/https_tests.rs` (tests only) and its declaration in `mod.rs`. No production code changes.

Working decisions (no CONTEXT.md; the user may override before execution):
- WD-16 The offline proof uses the `openssl` command-line tool as a test server (`openssl s_server`) and generates a throwaway key and certificate in a temporary directory, instead of adding a TLS server crate. No dependency is added, and no key material is committed. The tests are ignored by default (reason: needs the `openssl` binary) and have their own group filter, `tls_`.
- WD-17 The public-internet proofs are a separate ignored group, `net_`, and are never part of a gating command: a developer machine without internet access reports them as not run, never as passed.
- WD-27 The module is called `https_tests`, not `tls_tests`, on purpose: libtest group filters match the whole test path, so a module name that contained `tls_` or `net_` would pull the other group's tests into each filter (the `net_` tests would run, and fail offline, under the `tls_` filter). With this name each filter selects by test function name only.

Flagged assumptions (edge probe: FETCH-03 is `unclassified`, the user has not ruled): the certificate roots are those bundled with the HTTP client (plan 05-03, WD-11); the only way these tests add trust is the test-only `Egress::with_extra_root`. A TLS-intercepting proxy CA is not trusted by the host.
</objective>
