<objective>
Harden the token file, the one place a long-lived credential rests: refuse anything but a 0600 regular file of sane size, create files and the directory with tight permissions from the start, and add the per-alias lock, `mark_needs_login` and `delete` that login, refresh and logout need so they cannot overwrite each other.

Purpose: D-01 (0600, atomic, one file per alias), D-02 (a bad file disables only that plugin and is never silently treated as logged out, chmod'd or deleted), and the locking half of D-08 (refresh and login cannot lose each other's tokens). The lock uses its own file inside `<state-dir>/auth/`; it never takes the state directory lock `fili run` holds, so `fili auth` commands work while the host runs.

Output: a hardened `src/plugins/auth/store.rs` with its tests and one scheduler test.

Flagged assumptions (edge probe; the user has not ruled): the permission rule treats any group or other bit as too loose (mask 0o077) and does not check file ownership; symlinks are refused as a hardening step beyond D-02 (RESEARCH A8). Platforms without Unix permissions skip the mode check and its tests.
</objective>
