<objective>
Build the host's token endpoint client: exchange an authorization code, refresh an access token, and revoke a token, with the failure classification D-09 needs and the hardening D-13 requires.

Purpose: AUTH-01 (code exchange with PKCE), AUTH-02 (refresh and its permanent, transient and rejected outcomes) and AUTH-04 (revocation for logout, D-03). The client is a thin hand-written layer of three form POSTs on the async `reqwest::Client` that is already a dependency (no OAuth crate: provider quirks need escape hatches either way, RESEARCH Alternatives Considered). It is the host's own client, outside the plugin fetch allowlist and its egress policy, so plugin allowlists need not list login hosts.

Output: `client.rs`, four new `AuthError` variants, a `Reply::json` test helper, shared fake-endpoint helpers in `auth/testing.rs`, and the tests. Plans 06-06 (refresh in the provider), 06-07 (login) and 06-08 (logout) call it.

Flagged assumptions (edge probe; the user has not ruled): a client with no secret sends `client_id` in the request body and a client with a secret uses Basic auth (RESEARCH Open Question 2); a provider that needs Basic auth with an empty password for a public client (Reddit's installed apps) is not served here and is Phase 7's decision (an optional `token_auth` key can be added then without breaking existing TOML); a missing `expires_in` is left to the caller, which assumes 3600 seconds (RESEARCH A3); other 4xx OAuth errors are `Rejected` and never mark a login as needing renewal (RESEARCH A4); the User-Agent is `fili/<version>` for every provider (RESEARCH Open Question 3).
</objective>
