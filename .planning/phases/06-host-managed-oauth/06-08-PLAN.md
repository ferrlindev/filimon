<objective>
Finish the user-facing auth commands: `fili auth status` to see every stored login and its expiry state, and `fili auth logout <plugin>` to delete a login and revoke it at the provider on a best-effort basis.

Purpose: AUTH-04 and roadmap success criterion 4. `status` shows `needs_login` (D-09) and works while `fili run` holds the state lock; `logout` always deletes the local file and then tries to revoke (D-03), warning but succeeding when the provider call fails. This plan also removes the two dead-code allows earlier plans added, proving every item the phase built has a real reader.

Output: `status` and `logout` in `commands/auth.rs`, the `Status` and `Logout` variants in `cli.rs`, a lenient plugin-TOML probe in `config.rs`, the allow removals, and the tests.

Flagged assumptions (edge probe; the user has not ruled): `status` lists only sources that declare `[host.oauth]` or have a token file, so plugins with no authentication do not clutter the table; disabled sources are included because they can still hold a login; a plugin TOML that cannot be read is skipped with a stderr note unless it has a token file; `logout` of a disabled plugin deletes the file but cannot revoke, because a disabled plugin's `[host.oauth]` is not loaded, and says so; revocation sends the refresh token when one is stored, else the access token (RFC 7009).
</objective>
