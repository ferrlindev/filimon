<objective>
Prove the phase's central promise with two recording tests, prove the user-facing commands through the real binary, and document the feature.

Purpose: AUTH-03 (a plugin receives only a current access token and never a refresh token; ROADMAP success criterion 3 says "a test component that records everything it receives can confirm this") and AUTH-04 (status and logout as a user runs them). The recorder is proven twice: fast, with the scripted fake instance through the real scheduler including a rotating refresh, and for real, with the actual `stub-source` WebAssembly component through `Host::run` and the `run-once` path. The README makes the feature usable by someone who has not read the plans.

Output: the sentinel tests, an opt-in `record_inputs` setting in the stub guest, `tests/auth_cli.rs`, and the OAuth section of `plugins/README.md`.

Flagged assumptions (edge probe; the user has not ruled): AUTH-03 and AUTH-04 each had one unclassified edge; this plan resolves neither by user ruling, it covers them with the recording tests, the binary tests and the documented limits. A live login against a real provider cannot be automated (it needs a registered app and a browser); it is the manual check below. The real-component tests are ignored by default like all `wasm_` tests and need the rebuilt `stub-source` fixture.
</objective>
