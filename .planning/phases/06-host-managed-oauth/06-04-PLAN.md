<objective>
Build the front half of the login: the PKCE verifier, challenge and `state`, the authorize URL (with the plugin's `authorize_params`), and the one-shot loopback listener that receives the provider's redirect.

Purpose: AUTH-01 through D-04 (fixed `127.0.0.1` port, overridable), D-06 (5-minute wait, `state` verified, named errors for denied, mismatched and error callbacks, plain close-this-tab page, nothing secret printed) and D-14 (the extra authorize parameters). The listener is hand-written on tokio's `TcpListener` (about 150 lines): it needs exactly one GET with strict size and time caps, so no HTTP framework is added.

Output: `pkce.rs`, `callback.rs`, six new `AuthError` variants, two new direct dependencies, and the tests. Plan 06-07 composes these with the token client into `fili auth login`.

Flagged assumptions (edge probe; the user has not ruled): a stray callback with a wrong or missing `state` ends the login with `StateMismatch` as D-06 says (a local process can therefore abort a login by hitting the port; it can already do so by squatting it, and the user simply re-runs login); an `error=` callback is judged after the state check, so an unauthenticated `?error=` cannot print provider text; the provider's `error_description` is never shown.
</objective>
