## Decision: the `.env` format

Values are literal. `fili` never expands `$NAME` or `${NAME}` and never processes backslash escapes. It rejects every form that a shell-style dotenv reader would transform, or that can be read in more than one way. A file with any rejected line is unusable as a whole, and every rejected line is reported.

"Whitespace" below means `char::is_whitespace`.

Accepted:
- **F1 File.** Read once with `std::fs::read_to_string`. A missing file is an empty map. Any other read failure, including invalid UTF-8, is one DotenvInvalid with `line: None` and only the I/O error text. One leading U+FEFF (BOM) is skipped.
- **F2 Lines.** Split with `str::lines`, so LF and CRLF both work. Line numbers are counted from 1, never found by searching.
- **F3 Ignored lines.** Blank lines and lines whose first non-whitespace character is `#`. Comment text is never inspected, so it may contain `$`, quotes, anything.
- **F4 Assignment.** Optional whitespace, then an optional `export` followed by at least one whitespace character, then KEY, optional whitespace, `=`, optional whitespace, VALUE, TRAILER.
- **F5 KEY.** The first character is an ASCII letter or `_`; the rest are ASCII letters, digits, `_` or `.`. Case is kept, and lookup stays exact and case-sensitive.
- **F6 VALUE.** One of:
  - (a) empty: end of line, or at least one whitespace after `=` followed by a `#` comment. Reads as "".
  - (b) single-quoted: the text between the opening `'` and the next `'` on the same line, verbatim. It may contain `$`, backslash, `"`, `#` and spaces.
  - (c) double-quoted: the text between the opening `"` and the next `"` on the same line, verbatim. It must not contain `$` or a backslash.
  - (d) unquoted: the maximal run of non-whitespace characters, verbatim. It must not contain `$`, a backslash, `'` or `"`, and must not start with `#`.
- **F7 TRAILER.** Nothing, or at least one whitespace character followed by either end of line or a `#` comment.

Rejected. Each rejected line produces one `DotenvInvalid { line: Some(n), reason }`. The reason is the fixed phrase below and never contains line text. When a line breaks several rules, report the first one met scanning left to right.

| Rule | Line form | Reason text |
|------|-----------|-------------|
| R1 | `$` in a double-quoted or unquoted value | ``"`$` outside single quotes; fili never expands variables, so single-quote the value"`` |
| R2 | backslash in a double-quoted or unquoted value | `"backslash outside single quotes; escapes are not supported, so single-quote the value"` |
| R3 | `'` or `"` inside an unquoted value | `"quote inside an unquoted value; quote the whole value"` |
| R4 | unquoted value starting with `#` directly after `=` | ``"value starts with `#`; single-quote it, or put a space before a comment"`` |
| R5 | anything other than F7 after the value (`KEY=a b`, `KEY='a'b`, `KEY='a'#b`) | `"unexpected text after the value; quote the whole value"` |
| R6 | a quote not closed on the same line | `"unterminated quote; multi-line values are not supported"` |
| R7 | not blank, not a comment, not KEY=VALUE (bad key start or character, no `=`) | `"expected KEY=VALUE"` |
| R8 | a KEY already set on an earlier line | ``"duplicate key `<KEY>` (first set on line <N>)"`` (the key is an env var name, which diagnostics may carry) |

Accepted examples (input line, then value): `PLAIN=abc123` gives `abc123`. `export EXPORTED=v` gives `v`. `SPACED = v` gives `v`. `EMPTY=`, `EMPTY_SQ=''`, `EMPTY_DQ=""` and `EMPTY_COMMENT= # note` each give the empty string. `SQ='pa$$word \ "x" # y'` gives `pa$$word \ "x" # y`. `DQ="a b # c"` gives `a b # c`. `PADDED='  a  '` gives `  a  `. `HASH_INSIDE=a#b` gives `a#b`. `TRAILING=abc # c` gives `abc`. `QUOTED_TRAILING='abc' # c` gives `abc`. `UNICODE=bücher` gives `bücher`. `DOTTED.KEY=v` gives `v`. `lower_case=v` keeps key `lower_case`.

A value that holds `'` together with `$` or a backslash cannot be written in `.env`. The operator sets it in the process environment, which overrides `.env` (D-12). The docs say so.

**Why this format** (crate choice is Claude's Discretion, 01-CONTEXT.md):
- RESEARCH "Don't Hand-Roll" recommended `dotenvy`. Its 0.15 parser always substitutes `$` and cannot be configured, which is exactly CR-01 (reproduced in 01-VERIFICATION.md). Accepting shell semantics instead would still let `$NAME` read the real process environment, and would fail the verifier's "never reads the real process environment" test. That leaves the two closures the verifier named: verbatim, or reject. This plan does both: literal values, plus rejection of every ambiguous form.
- Rejecting, rather than silently reading `$OTHER` literally, keeps the project's fail-closed rule. An operator who meant substitution sees an error instead of a wrong secret.
- **Reversibility: reversible.** Every accepted line reads the same under any later choice, because ambiguous forms are never accepted. A future release can give R1-R8 a meaning without changing any value `fili` accepts today. The parser sits behind the existing `read_dotenv` seam, and D-12 precedence is untouched. No checkpoint is needed.
