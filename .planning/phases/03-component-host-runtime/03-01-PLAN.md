<objective>
Wave 0 consent gate for the toolchain change. The repository is pinned to Rust 1.85.0 by a machine-local `rustup override`. The Phase 3 host needs wasmtime 48 LTS, which needs Rust >= 1.95. Under edition 2024 with `rust-version = "1.85"` cargo silently resolves `wasmtime` to 34.0.2, an unsupported release, so the override must go before any task that runs plain `cargo` against the new dependency (RESEARCH Pitfall 1, Open Question 1).

Purpose: the one step no agent may take on the user's behalf. Everything else in the toolchain move (root `rust-toolchain.toml`, `rust-version`, nested SmartModule pins, README) is plan 03-03 and runs after this gate.
Output: the override removed, confirmed by `rustup override list`.

Reversibility: the change is reversible. `rustup override set 1.85.0` in the repository root restores the previous state. SmartModule builds keep Rust 1.85.0 through nested pins (plan 03-03), so the README rule "Rust 1.96+ breaks SmartModule linking" still holds for them.

Assumption recorded (RESEARCH A1, Open Question 1): wasmtime 48 LTS (Rust >= 1.95) is preferred over wasmtime 36 LTS (Rust >= 1.86) because the support window is longer. If the user refuses a toolchain >= 1.95, stop here and re-plan the phase on wasmtime 36 (one code difference: the engine setting that turns on async support is required on 36).
</objective>
