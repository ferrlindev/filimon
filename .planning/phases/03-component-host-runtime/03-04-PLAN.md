<objective>
The tracer slice for the whole phase: one registry-listed source (the prebuilt `stub-source` component) is loaded, instantiated, initialised, polled, mapped to a `SourceItem`, handed to a sink, and its cursor persisted, wired through every layer the phase will modify. Task 2 then proves restart-resume on the same slice.

This is production code: the host is async on wasmtime 48 LTS with epoch yielding enabled, one tokio task per enabled source, a fixed-delay wait after each cycle, and a pure-`std::fs` atomic cursor store. Plans 03-05 to 03-10 only deepen these files (state machine, loader checks, item validation, Fluvio sink, cursor policy), they do not reshape them. Single-path error handling here is deliberate: every non-success outcome ends that one plugin's task with a logged `disabled` reason; the D-01..D-04 backoff and rebuild behaviour is plan 03-06.

Purpose: prove the architecture end to end (HOST-01 registry-only loading path, HOST-02 poll and persist and resume, HOST-04 WIT item to `SourceItem`) on the first and best context, so a dead end shows up after one commit.
Output: `src/plugins/host/` (ten source files plus `testing.rs`, `wasm_tests.rs`), `pub mod host;` in `src/plugins/mod.rs`. One file per layer: tracer scope is vertical, each file is a complete implementation of its narrow job and later plans extend it.

Locked decisions implemented here: D-05 (JSON file per alias, atomic, opaque bytes as base64; costly), D-06 (default `.fili-state/` next to the registry; the flag is plan 03-05), D-07 (commit only after send and flush), D-08 (a corrupt or unreadable cursor file disables only that plugin; never resets to none), D-02 (per-plugin tasks only; the backoff arithmetic is 03-06).
