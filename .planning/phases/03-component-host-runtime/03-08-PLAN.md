<objective>
Finish HOST-04: items a plugin returns are validated, mapped to `SourceItem` records and produced to Fluvio, with the producer's sticky-error behaviour handled so one failed batch cannot wedge the sink.

Purpose: success criterion 2 (items appear in a Fluvio topic as `SourceItem` records). Plugin output is untrusted input and the consumer does no id or url validation (verified in research), so the host is the only gate. Plan 03-04 mapped items 1:1 with no validation; this plan adds the gate and the real sink.
Output: validation in `map.rs`, `FluvioSink` and `live_` test support in `sink.rs`, `TypedProducer::clear_errors` in `streaming.rs`.

Decisions recorded (RESEARCH Discretion Resolutions 6, A4, A5; Claude's discretion):
- Drop rules and the 1_000_000-byte cap come from the verified Fluvio default `max_request_size` of 1_048_576, leaving headroom for framing. Thresholds are judgement (A5), not user decisions.
- Key `"{platform}:{id}"` (A4). The alternative, key = plugin alias, preserves per-plugin order on multi-partition topics; choose it only if operators create multi-partition topics. Not confirmed with the user.
- Dropped items do not block the cursor: the poll still counts as a success and the `dropped` counter is surfaced in the report.
</objective>
