<objective>
Operator-facing wiring for the host: the `--state-dir` flag / `FILI_STATE_DIR` env var that D-06 asks for, and a `tracing` subscriber so the host's required logging (D-03, D-04, HOST-05: "logged with its plugin name") is actually visible.

Purpose: without a subscriber every `tracing::warn!` the host emits goes nowhere; without the flag an operator cannot move the cursor directory. Both are flags and wiring, not subcommands, so the Phase 4 command surface is not pre-empted (RESEARCH Discretion 2).
Output: a `state_dir` argument in `src/cli.rs`, `init_logging` in `src/main.rs`, and unit tests for both.

Decisions recorded:
- RESEARCH Open Question 2 (should the default filter change existing commands' output?): no. The default is limited to plugin-host events, so Phase 1-2 commands behave exactly as today. Operators opt in with `RUST_LOG`. The one existing plugin event (`resolved plugin secrets` in `src/plugins/config.rs`, which prints env var NAMES only) now shows when a registry is loaded; no command loads one yet.
- Correction to RESEARCH A3: the directive is `fili::plugins=info`, derived from `env!("CARGO_CRATE_NAME")` so it can never drift from the real crate name.
</objective>
