# Milestones

## v1.0 WASM Source Plugins (Shipped: 2026-11-15)

**Phases completed:** 8 phases, 65 plans, 101 tasks

**Closeout type:** override_closeout

**Known verification overrides:** 2 newly acknowledged, 0 carried forward (Phase 02 docker-compose items: unused `OUTPUT_PATH` env var; `stream` subcommand missing). The readiness check reported phases 1-6 and 8 as stale; the user proceeded on the 2026-11-15 milestone audit (status `tech_debt`, 41/41 requirements). Live Reddit proof waived (TEST-04). Tech debt is listed in `milestones/v1.0-MILESTONE-AUDIT.md`.

**Key accomplishments:**
- Versioned WIT package `filimon:plugin@0.1.0` with `source` and `fetcher` worlds, plus two cargo-component stub guests that build from `../../wit` alone for wasm32-unknown-unknown and pass `wasm-tools component targets` for their world.
- `filimon.toml` registry, per-plugin TOML and `.env` load into a typed `LoadedRegistry` (toml 1 spans, dotenvy without env mutation, thiserror and miette diagnostics), with alias-keyed per-plugin secrets in a redacting `Secret` newtype.
- A committed `examples/plugins/` sample (stub, Reddit and YouTube sources, stub and http fetchers, empty `.env.example`) is proven by test to load into typed config with per-plugin secret isolation. A new global `fili --registry` flag (env `FILI_REGISTRY`, default `filimon.toml`) selects the registry.
- dotenvy is gone. `.env` values are now read literally by a strict parser in `secrets.rs`: `KEY='pa$$word'` delivers `pa$$word`, and any `$`, backslash or other ambiguous form outside single quotes is rejected with its line number and no value text. A broken `.env` no longer triggers false MissingSecret errors, and EmptySecret names the process environment or the `.env` path as the source.
- `registry_flag_defaults_to_filimon_toml` now asserts `filimon.toml` through `Cli::command()` argument metadata (`get_default_values()`), so an exported `FILI_REGISTRY` can no longer turn it into a silent pass.
- News pages now travel as `SourceItem`s on `filimon-raw-pages`. `fili consume` runs the unmodified map-preprocess, map-extract and filter-relevance chain on that stream itself (retries disabled, preflight first) and writes a JSON array of unified `OutputRecord`s with RFC 3339 dates and no html.
- Social `SourceItem`s now travel on `filimon-social-items` with no SmartModules. `fili consume` merges that plain stream with the news chain stream through `futures_util::stream::select`, labels every record by its topic of origin, runs NER on social title+text (capped at 500 chars) as well as news, and writes both kinds into one JSON array. `--source` narrows the streams and preflight, and `--output` picks the file.
- README now walks an operator through both topics, a news and a social `SourceItem`, and one `fili consume` JSON array. That path was run live on the local cluster from README's own sample lines. The codebase map describes the consumer-side chain and the social topic, and no doc names the retired articles topic.
- Consume diagnostics are now built only from fixed text, topic, offset and serde_json's error class and position. SmartModule hints are cut to the module-authored prefix, and every diagnostic reaches stderr through one `sanitize_for_terminal` choke point. This closes the 02-01/02-02 "no diagnostic carries the record value" gap and CR-01.
- Past the 100-message cap, a batch run now names every dropped record by topic and exact offset. Skipped records and notes go into separate per-topic `OffsetRanges` that are printed as range lines through `print_diagnostic`. This closes verification gap 2 without changing the WR-06 budget or cap.
- All three published conversions (social RFC 3339, social epoch ms, news best-effort) now format through one private `utc_rfc3339` that returns None for a UTC year outside 0000..=9999, so chrono's signed `+10000-...` / `-0001-...` output can no longer reach the JSON. This closes gap 3 / WR-09.
- A social record and its notes now travel as one `Incoming::Noted` item, and notes no longer count toward the diagnostic budget. No limit, budget, idle or end-of-stream stop can leave a note about a record that was not written, in the single stream or the merged one.
- The user removed the machine-local rustup override that pinned this checkout to Rust 1.85.0, with Rust 1.96.0 and 1.85.0 both still installed, clearing the way for the wasmtime 48 LTS toolchain move in plan 03-03.
- Global `--state-dir`/`FILI_STATE_DIR` flag (no default) plus a stderr `tracing_subscriber` with a `fili::plugins=info` default so host warn/error lines become visible.
- Versioned, plugin-checked, atomically written cursor state files with a per-directory single-instance lock, plus nine scheduler tests that pin commit-after-flush and never-reset-a-bad-file policies, all without wasm or a cluster.
- `fili plugins list` reads a lock-free `<alias>.status.json` sidecar that the scheduler writes after every cycle outcome, runs as the real binary with no banner, and the empty `--state-dir` carry-over (WR-07) is refused by clap and by the store.
- Host::run now stops within a 10 s grace after shutdown (second signal aborts at once), reporting each cut-off plugin as `aborted at shutdown`, via a generic `supervise` tested under paused time.
- `fili plugins list --json` prints one parseable JSON array through the real binary, and `list` is now covered for every status shape, broken plugin, held lock, hostile status text and exit code, with skipped registry names reported on stderr.
- `fili plugins check <name>` validates one plugin without polling it: the component goes through the host's own preflight (`check_component`, no second checker) and its TOML and `.env` secrets through a plugin-scoped config loader, with exit 1 and a diagnostic naming plugin, path or field on any failure and no secret value ever printed.
- `fili plugins run-once <name>` polls one source once and prints its items (table, or compact `SourceItem` JSON lines with `--json`); without `--produce` it never sends, locks or writes anything, and with `--produce` it sends the batch and only then saves the cursor under the state-directory lock, reusing the scheduler's own secret-exposure site, cursor-size rule and `send_records`.
- `fili run` polls every enabled source plugin on its interval into Fluvio until stopped: strict load, honest startup report, SIGINT/SIGTERM graceful stop with a second-signal abort, a per-plugin summary and a defined exit rule, over a generic sink so everything but the one production connect is tested without a cluster.
- A source's `fetch` import now runs the registry-assigned fetcher component in a fresh wasmtime instance per call, behind an exact-host allowlist that refuses before any fetcher starts.
- `plugins/http-fetcher`: a `fetcher`-world component whose `fetch` logs one fixed line and returns `send(&request)` unchanged, built from `../../wit` alone and registered as `[fetchers.http]` in the sample registry.
- A fetcher's `outbound-http.send` now reaches the network through one shared certificate-validating client, under the calling source's own allowlist and deadline, with redirects followed and re-checked by the host (five at most), credentials dropped across origins, and bodies capped at 8 MiB.
- `FetchPolicy::check` now refuses a `host` header, framing and hop-by-hop headers, malformed headers and oversized urls, bodies and header sets before any connection, at both the source's `fetch` and the fetcher's `send`, and tests show headers, binary bodies and a 429 pass through faithfully while the host's logs hold no header, body, query or path.
- The host's HTTPS path is shown, not assumed, to validate certificates: a local openssl TLS server with a self-signed certificate is rejected by the production client and by the real default fetcher component, accepted only when its certificate is explicitly trusted, and rejected again for a name the certificate does not cover, with an always-on guard keeping the invalid-certificate switch out of `fetch.rs`.
- On real wasm components the registry's `fetcher` line alone decides who serves a source's request, the allowlist and the per-call timeout hold for the default fetcher and for a hostile custom one (steered by an `x-stub-mode` header on the stub fetcher), and `fili plugins run-once` now builds the same fetch route as `fili run`.
- `fili produce` can fetch its pages through a fetcher component named by a `[crawler]` registry table, under the host's seed-host allowlist, redirect re-check and timeout, and never silently falls back to the certificate-skipping built-in client.
- READMEs, WIT comments and the sample registry now state exactly what the fetcher layer enforces and what it does not, and the whole phase's unit, real-wasm and TLS groups pass together (433 / 41 / 5).
- A plugin's `[host.oauth]` TOML, a per-plugin atomic token file and a clock-injectable token provider now deliver the stored access token to the guest's `poll` in both the scheduler loop and `fili plugins run-once`, with the WIT contract untouched.
- The token file is now only ever a small 0600 regular file this host wrote (anything else is refused by name and left alone), and login, refresh and logout get a per-alias advisory lock plus lock-guarded `mark_needs_login` and `delete` that never touch the state lock `fili run` holds.
- `[host.oauth]` now takes `client_secret_env`, `revocation_url`, `redirect_port` (default 17420) and `authorize_params`, rejects every bad endpoint, port, scope and reserved parameter with plugin and field named in one report, and resolves the client secret through the Phase 1 `.env` rules into a field the guest's `init` can never receive.
- RFC 7636 S256 PKCE (CSPRNG verifier and state, authorize URL with the plugin's extra parameters) and a hand-written one-shot `127.0.0.1` callback listener that verifies `state`, rejects hostile traffic, serves a fixed page and never prints a code, verifier or state.
- Hardened async token client: PKCE code exchange, refresh with permanent/transient/rejected classification, and revocation, with no credential or provider body ever reaching an error text
- Lazy OAuth refresh before every poll: an in-process gate plus the per-alias lock, a re-read after locking, the new login saved atomically before its token is used, and D-09 failure classes wired into the scheduler and `fili plugins run-once`.
- `fili auth login <plugin> [--no-browser]` runs the whole PKCE flow (loopback listener, authorize URL with authorize_params, code exchange with the matching verifier) and writes the 0600 token file only after the exchange succeeded, printing no secret.
- `fili auth status` (lock-free, creation-free, fixed-key `--json`, never a token) and `fili auth logout <plugin>` (local delete under the per-alias lock first, then best-effort RFC 7009 revocation), with the auth module's dead-code allows removed.
- Sentinel recording tests prove a plugin holds only an access token (fake scheduler run through a rotating refresh, and the real stub-source wasm through Host::run and run-once), ten binary tests drive fili auth, and the plugins README documents the whole OAuth feature.
- Standalone `plugins/reddit` crate: a validated-settings Reddit app-only poll of subreddit listings behind an `Http` trait, replayed natively from a synthetic fixture and built to a world-conformant `reddit_source.wasm` with no WASI imports.
- `[host.oauth]` now accepts `grant = "client_credentials"` (app-only, no login, host-held secret) and an optional validated `user_agent`, with named never-echoing diagnostics and every existing plugin TOML loading unchanged.
- Host-side Reddit app token: Basic-auth `client_credentials` request, in-memory single-flight cache with a 60 s renewal margin, and an operator-set User-Agent for token and revocation calls.
- Standalone `plugins/youtube` crate that polls channel uploads playlists through `playlistItems.list` with an `x-goog-api-key` header, tracks a per-playlist publication mark, and builds to a world-conformant `youtube_source.wasm` with no WASI imports.
- Reddit responses are classified before parsing: 429 or `x-ratelimit-remaining` below 1 returns `rate-limited` with the float-parsed reset seconds, every other failure is a named typed error, and a strict-mock sweep plus a fixture manifest test prove compliance and fixture completeness.
- The `reddit-user` instance polls the logged-in home feed by a `created_utc` mark and saved posts by a 25-fullname seen set (D-19), answers `auth-required` without a login, and leaves every existing time-mark cursor byte-identical.
- `fili auth login` refuses a `client_credentials` plugin with a clear reason before touching any secret, `fili auth status` shows it as `app-only`, and `plugins/README.md` documents the grant, `user_agent`, and the Reddit and Google provider notes.
- All Reddit and YouTube fixtures stay `synthetic` by the user's D-21 ruling; the offline gate (native suites, both components, `plugins check` for four instances, host suite) ran and is green, with two acceptance-criterion regex discrepancies reported below.
- A fixture-serving `replay-fetcher` component plus an in-crate harness that runs the real Reddit and YouTube components through the host with replayed HTTP and lands exactly the fixture `SourceItem`s in a scratch Fluvio topic (or an in-memory sink), skipping cleanly when no cluster is reachable.
- A copy-and-rename `plugins/template` source crate plus `scripts/verify-authoring.sh`, which builds it in a temp directory outside the repo against only the published WIT (local `git archive` or a sparse clone at a ref) and shows the unmodified `fili` binary checks and polls it.
- One re-runnable `scripts/live-e2e.sh` runbook for the human-run live E2E: named preflight failures, a Reddit stop-and-ask gate (exit 3), the run, and a sanitiser plus secret scan whose safety logic is proven hermetically by `selftest`.
- `scripts/verify-authoring.sh` gains a fetcher leg (a fetcher built outside the repo from a copy of `plugins/stub-fetcher` serves the template source's requests through the registry assignment), and `docs/plugin-guide.md` documents the whole source and fetcher authoring path, pinned to tag `wit-v0.1.0`.
